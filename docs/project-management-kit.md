# Project Management Kit

## 1) Backlog structure
Use one master backlog with:
- **ID**
- **Title**
- **Type** (feature/bug/ops/risk)
- **Owner**
- **Priority** (P0/P1/P2)
- **Status** (Now/Next/Later)
- **Acceptance criteria**
- **Dependencies**
- **Target sprint**

## 2) Sprint model
- Sprint duration: **2 weeks**
- Sprint ceremonies:
  - Planning
  - Mid-sprint check
  - Demo
  - Retrospective

## 3) Weekly owner review template
- What was completed?
- What is blocked and why?
- KPI trend updates.
- Decisions required this week.
- Top priorities for next sprint.

## 4) KPI review template
- Task acceptance time (target vs actual)
- Time-to-completion (target vs actual)
- Repeat complaints (%)
- Payment success rate (%)
- Staff utilization by area
- Customer rating/NPS

## 5) Risk register template
- **Risk**
- **Impact**
- **Likelihood**
- **Owner**
- **Mitigation**
- **Trigger condition**
- **Escalation level**

## 6) Idea Vault template
- **Idea**
- **Problem solved**
- **Expected impact**
- **Effort estimate (S/M/L)**
- **Priority score**
- **Decision** (keep/defer/drop)

## 7) Definition of Ready (DoR)
An item is ready when:
- User outcome is clear.
- Acceptance criteria are written.
- Dependencies are identified.
- Owner is assigned.

## 8) Definition of Done (DoD)
An item is done when:
- Acceptance criteria pass.
- Role/access implications are validated.
- Metrics/event tracking is defined where needed.
- Relevant SOP or change log is updated.
